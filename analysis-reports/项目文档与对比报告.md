# 第一部分：天枢项目文档

## 1. 项目概览

| 项 | 内容 |
|---|---|
| 名称 | 天枢 Tianshu-harness（开发代号 Rivet，数据目录仍为 `~/.rivet`） |

### 核心理念：认知虚拟机（CVM）

「模型提供认知能力，CVM 提供认知执行语义」。围绕这个理念构建了四层防御体系：

1. **星域信念注入**（static prompt）——冻结前缀中的信念层；
2. **Courage Hook**（preTurn）——每回合前的勇气阈值拦截；
3. **Sensorium**——每 turn 六维状态感知；
4. **RuntimeHookPipeline**——五阶段 hook 管线拦截退化行为。

配套三大差异化卖点（docs/architecture-overview.md）：

- CVM 五阶段 RuntimeHookPipeline（`src/agent/hooks/` 下 75 个 hook 模块）；
- **Prefix-cache-first** 架构：冻结前缀 + 增量 appendix + 边界压缩，宣称全模型 95–99% 稳态缓存命中率；
- **星域纪律**：16 套可切换认知姿态（提示词 / 决策阈值 / 勇气阈值），非角色扮演。

## 2. 六层架构

```
Layer 0 Surfaces:   TUI(src/tui/engine) · Desktop(Tauri,闭源) · VS Code 插件 · Headless · sidecar HTTP/SSE(src/server)
Layer 1 Agent Loop: src/agent/  loop.ts → turn 编排 → 工具执行 → 补全
Layer 2 Context:    src/context/ + src/memory/  CognitiveLedger · ClaimStore · Stigmergy · TaskContract
Layer 3 Prompt:     src/prompt/ + src/compact/ + src/cache/  三段式提示词与压缩
Layer 4 Tools:      src/tools/ + src/repo/ + src/search/ + src/lsp/，kernel 预算 ≤26 工具
Layer 5 API/Model:  src/api/ + src/model/ + src/auth/
```

**闭源边界**：`desktop/`（Tauri+React 桌面端，约 450 文件）与 `src/pro/`（Pro 模块、computer-use 桥、执行隔离）不在公开仓，经 sync 排除（EXTERNAL-PRS.md）。

## 4. 功能特性清单

### 4.1 模型接入（src/api/，115 文件）

独立客户端：Anthropic（Claude）、OpenAI 兼容端点、Codex（OAuth PKCE，ChatGPT 订阅）、Gemini 原生协议、DeepSeek 平台通道（含 Spark）、OpenAI Responses API、生图端点；基础设施含 FallbackStream 降级链、重试引擎、限流、错误分类、成本模型、tool-call JSON 修复。

# 第二部分：DeepSeek Harness 概览

| 项 | 内容 |
|---|---|
| 名称 | DeepSeek Harness，CLI `dsh`，npm 包 `@deepseek-ai/dsh` |
| 版本 / 协议 | v0.1.2-alpha.1（developer preview，明示破坏性变更），MIT |
| 出品 | DeepSeek AI 官方开源 |
| 技术栈 | TypeScript strict + Node 22.19+/24，pnpm 11.7 monorepo（268 个 package.json），全 ESM |
| 一句话概括 | 基于「万物皆插件（Cordis）」架构的 agent harness，主形态是 Web UI / SDK / ACP，而非终端 |

## 核心架构

- **Cordis 框架底座**（上游 vendored 进 `vendor/cordis`）："Every part of the product is a plugin, including the model adapter, the tool registry, the session log, and the agent loop itself"；
- **组合模型**：Profile（web/headless/sdk/sdk-minimal/acp 五模板）+ Bundle（7 个）+ `cordis.patch.yml` 覆盖任意行，`--dump-config` 可 dump 整棵插件树；
- **能力缝（capability seam）**：每项能力 = Service Definition / Provider / Consumer 三角；fs/subprocess 换 provider 即整体迁移到远程沙箱；
- **铁律 "Model-visible ⟺ logged"**：到达模型请求的一切必须可从 append-only SessionEvent 日志重建，有运行时不变量断言。

## 规模与工程

- `packages/` 46 个包组、406 个二级目录；TS 源 **2,806 个文件约 59.5 万行**；测试 **842 个 .spec.ts**；
- **逐文件 100% 覆盖率门禁**（vitest + 自研 reporter）；179 个 scripts、60+ 自定义 verify/gen 门禁；
- 文档 **238 篇全部中英双语配对**（有翻译配对门禁）+ 40 个子系统页 + VitePress 站点 + **1,624 篇带日期的 Agent Notes** 决策记录；
- 双 SDK：TS SDK + Python SDK（stdio JSON-RPC，按平台分发 wheel）；
- 沙箱：Linux Landlock 原生启动器、Windows ACL、E2B 远程沙箱 POC；SAFETY.md 明示未经安全审计。

# 第三部分：特色对比（差异化定位）

| 维度 | 天枢 Tianshu-harness | DeepSeek Harness |
|---|---|---|
| **产品哲学** | 认知虚拟机（CVM）：给 agent 套一层「认知执行语义」——信念注入、勇气阈值、状态感知、hook 拦截退化行为 | 万物皆插件：agent 运行时 = 按序叠加的 Cordis 插件树，连 agent loop 本身都是插件 |
| **首要形态** | **终端 TUI**（纯 ANSI 自研引擎，零 React/Ink），桌面端/IDE 插件经 sidecar 驱动同一内核 | **Web UI**（React+Vite，43 个 UI 包）+ Electron 桌面端 + 双 SDK + ACP server，**没有 TUI** |
| **核心卖点** | Prefix-cache-first（宣称全模型 95–99% 缓存命中率）+ 证据驱动交付门禁（GREEN/YELLOW/RED） | 架构可组合性（profile+bundle+patch 分层覆盖）+ "Model-visible ⟺ logged" 会话可重建不变量 |
| **模型策略** | **多模型平等接入**：9+ provider 独立客户端 + 任意 OpenAI 兼容端点，缓存架构对全模型生效 | **DeepSeek 优先**：官方直连通道 + pi-ai 多 provider 适配器兜底（OpenAI/Anthropic/兼容网关） |
| **成熟度** | v3.28.0，28 个版本发布记录，Apache-2.0，已对外发布五平台二进制 | v0.1.2-alpha.1 developer preview，MIT，明示破坏性变更、无兼容性承诺 |
| **开源策略** | 双仓模型：公开仓是开发主仓的同步投影，桌面端与 Pro 模块闭源 | 全量开源 monorepo（含 vendor 的 Cordis 框架源码） |
| **文化气质** | 东方星象叙事体系（16 星域、经络、黏菌、碑文），工程浪漫主义 | 工程实证主义：生成目录门禁、双语翻译门禁、1,624 篇决策记录、逐文件 100% 覆盖 |
| **目标用户** | 终端重度用户 / 个人开发者（手机遥控审批、Termux、WSL 都有支持） | 平台型开发者 / 二次开发者（SDK、ACP、webhook、bundle 分发、第三方插件生态 GitHub topic） |

**一句话总结**：天枢是「把认知科学做成终端产品」的单体运行时；DeepSeek Harness 是「把运行时拆成乐高」的插件化平台底座。一个向内做深认知层，一个向外做宽组合面。

# 第五部分：结论

## 相同点

两者都是 TypeScript strict + Node 24 + 全 ESM 的 agent 运行时；都有完整的工具集、MCP、子代理、沙箱、审批机制；都走「CLI 命令 + 多端消费同一内核」的路线；工程纪律都远高于同类项目平均水平。

## 本质差异

| | 天枢 | DeepSeek Harness |
|---|---|---|
| 创新层次 | **认知层**：agent 的「心智状态」是一等公民（CVM、星域、Sensorium、Courage） | **架构层**：运行时的「组合方式」是一等公民（插件树、能力缝、profile/bundle） |
| 优化焦点 | 成本与稳定性：前缀缓存命中率、证据门禁、交付质量 | 可重建性与可扩展性：会话日志不变量、能力缝替换、插件生态 |
| 交付形态 | 一个开箱即用的**终端产品** | 一套供组装的**平台底座**（Web/SDK/ACP 都是装配结果） |

## 互相可借鉴的点

- **天枢可向 dsh 学**：能力缝三角的形式化（fs/subprocess 换 provider 即迁移沙箱）、"Model-visible ⟺ logged" 的运行时不变量断言、逐文件 100% 覆盖门禁、双语文档门禁、委派外部 agent（Claude Code/Codex）作为子代理。
- **dsh 可向天枢学**：前缀缓存架构（dsh 目前无对应设计，长会话成本偏高）、终端 TUI（dsh 完全缺席终端形态）、交付门禁（GREEN/YELLOW/RED 证据驱动交付）、办公套件与浏览器等 EXTENDED 工具面、移动端支持。
