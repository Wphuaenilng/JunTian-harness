# 0001. 单仓与全栈自主可控

> 编号规则：`decisions/` 下 NNNN 单调递增、绝不复用；被推翻时本文件状态改
> `superseded` 并在替代者的 frontmatter 里写 `supersedes: decisions/NNNN-xxx.md`，不删档。

## Status

accepted（2026-10-16）。落地动作见 Decision 第 1–6 条，本文件只作决策记录。第 1–5 条已于 2026-10-16 落地（**尚未提交**，改动清单与门读数记在 `client/README.md` 的 ④⑥ 两格）；第 6 条（产品名统一改名）仍未开始，按计划独立一轮做。

## Context

几股互相拉扯的力，逐条带 2026-10-16 现测：

1. **文档前提与 remote 现实已经分叉。** `AGENTS.md:3` 写"本仓是开发主仓的同步投影"，`:29` 写"桌面端（`desktop/`）与部分高级实现不在本仓（闭源边界见 EXTERNAL-PRS.md）"。但 `origin` 指向 `Wphuaenilng/JunTian-harness`，GitHub API 现测 `private:false`、`visibility:public`、`license.spdx_id:Apache-2.0`——本仓已是唯一事实源，不存在上一层不公开的 dev 仓。
2. **桌面端不再是外部拿来的产物。** 现在做的是本仓 `client/`（`apps/web`、`apps/desktop`、`packages/ui-*`）自研的 Web 桌面端，走 sidecar HTTP/SSE 驱动同一内核；而 `AGENTS.md:29` 指向的那个 `desktop/`（Tauri）**盘上不存在**（现测 `ls -d desktop` 无结果）。
3. **"闭源边界"这个说法在仓内没有事实源。** `AGENTS.md` 把边界指向 `EXTERNAL-PRS.md`，而那份文件 54 行通篇只讲外部 PR 处置流程，一条边界清单都没有。全仓"闭源"字样只散落在代码注释（`src/api/pro-registry.ts`、`src/__tests__/npm-pack-boundary.test.ts` 等）与历史发布记录里。
4. **pro 分层机制是真的，但它的对端不在仓内。** 现测 `src/pro/` 不存在，而注册表、动态 import、`tsup.config.ts` 的独立 entry、包边界测试都还在。也就是说这些注释描述的是"一个本仓没有另一半的缝"。
5. **对外承诺了一个发不出的东西。** 四份 README（中/英/日/韩）共 6 处指向 `JunTian-harness/releases/latest` 的桌面端安装包；现测该仓 **Releases 为 0 个**——历史 101 个 tag 能推过去，Release 资产在服务端带不走。
6. **改名尚未发生。** 产品名"天枢 / CLI 命令 `rivet`"与主体名"钧天 · Juntian Works"的分层还没统一，这是独立一轮全仓机械替换，不能和口径纠正混在一笔里。

## Decision

1. **取消双仓叙事。** `AGENTS.md:3`（本仓是开发主仓的同步投影）、`:29`（桌面端与部分高级实现不在本仓，闭源边界见 EXTERNAL-PRS.md）、`:33`（移植进开发主仓）与 `CLAUDE.md:3`（桌面端 `desktop/`：Tauri + React，闭源）里的这层叙述删除，改为单仓口径：本仓即唯一事实源。另 `.rivet.md:3` 末句"桌面端 `desktop/` 是独立 React 应用"指向盘上不存在的目录，桌面端落点改 `client/`。
2. **保留外部 PR 的处置政策，只换前提。** "不在本仓直接 merge，内容由维护者按当前代码重写后落地、以 `sync-merged` 关闭、署名两本账（`credit: PR #N` 提交 + `CREDITS.md` 逐行）"整套保留——它防的是分叉与未验证代码进本体，跟闭源无关。`EXTERNAL-PRS.md` 与 `CONTRIBUTING.md` 按单仓改写措辞。
3. **桌面端的事实源改为 `client/`。** `docs/desktop-guide.md`（正文讲 Tauri）状态改 `deprecated`、不删档；对外文档里"桌面端"一律指向 `client/`。
4. **删掉发不出的承诺。** 四份 README 的桌面端下载段改为"从源码运行；安装包尚未发布"，不保留 `releases/latest` 死链，也不保留展示 Tauri GUI 的首屏截图作为桌面端现状。
5. **pro 分层机制不拆，只改注释口径。** 把"闭源边界 / 闭源实现"改写为"未实现的扩展缝，对端不在本仓，无开源发布计划承诺"。`src/__tests__/npm-pack-boundary.test.ts` 那条包边界安全门**留着**——它防的是将来任何 pro 产物被 minify 后当开源包发出去，与叙事无关。
6. **产品名统一改名独立一轮。** 本轮所有文档沿用"天枢 / rivet"，避免机械替换与语义纠正混在同一次 diff 里。

## Consequences

**正面**

- 文档不再宣称本仓之外还有一个事实源，`AGENTS.md` 与 `origin` 一致。
- 桌面端有了单一落点（`client/`），不再同时存在"闭源 Tauri 桌面端"与"本仓 web 桌面端"两套叙述。
- 死链消失，避免访客在第一屏就撞到不存在的安装包。
- 外部贡献者的待遇与署名机制不变，`CONTRIBUTORS.md`/`CREDITS.md` 两本账继续记。

**代价与风险**

- 改动面横跨 `AGENTS.md`、`CLAUDE.md`、`.rivet.md`、`EXTERNAL-PRS.md`、`CONTRIBUTING.md`、四份 README、`docs/desktop-guide.md`，且四份语言版本必须同步改，漏一份就是自相矛盾。
- `docs/desktop-guide.md` 标 `deprecated` 后，其正文（`:3` 那句"适用于天枢桌面端（Tauri）"是全文唯一的 Tauri 定位句，另有 15 处"桌面端"表述）转为历史记录，不再是"当前桌面端怎么用"的答复来源。
- pro 那几处注释改口径后存在误读风险：读者可能以为 pro 功能即将开源，所以注释必须同时写明"对端不在本仓、无发布承诺"，不能只删"闭源"二字。
- 历史文档不动：`docs/releases/*`（如 `v3.1.0.md:55`、`v3.2.1.md:46`）、星域叙事文案、`docs/engineering-metrics.md:77`（那是说 Claude Code 闭源）、`THIRD-PARTY-NOTICES.md` 的设计出处登记一律保留——改掉它们是篡改历史，也断 Apache-2.0 下的署名链。
- `docs/superpowers/specs/2026-05-21-open-closed-source-decision.md`（"天枢开源/闭源决策记录"）是本文取代的对象，但**原文不在盘上**，只有 `docs/INDEX.md` 与 `docs/docs.json` 挂着链接；因此本文 frontmatter 不写 `supersedes`（写了就是指向不存在文件的假宣称）。
- **索引两份不在本轮改动内**（2026-10-16 现测后改口，本条原写"改在索引侧修那条链接"，那是没验过的推断）：`docs/INDEX.md` 头部自称「共 1035 篇」，而本检出盘上只有 358 个 `.md`，`npm run docs:index` 在这里会把索引砍到 190 篇（生成器 `scripts/docs-index.ts:460` 对覆盖不足只警告、不判失败）。索引三件套是构建产物，手加一条 0001 的 diff 会在下一次完整检出重建时被静默丢弃，还与该文件自己的计数行互相打脸。那条死链接由 `npm run docs:check` 按"子集检出"tolerate（现测 exit 0，13 条 ⚠ 未增加），真正的修法是在完整树上重建索引。
- 商标与平台 ID 未实测，本文不作"已注册"之类表述。
